## 2. 共同视觉与动作骨架

每招先明确**剑在哪里、朝哪里运动、何时击中**，再增加光、雾与碎屑。实体剑保留剑身、剑尖与护手；气剑也保留剑的轮廓。命中峰值集中在剑锋或目标局部，持续状态在人物与地面附近保持清楚的边界。

表现分为准备、释放、飞行／位移、命中、持续、消散。只有需要的阶段才制作：单次攻击不用留下领域，模式切换不用播放一套绝技，持续领域在周期攻击之间保留疏朗的循环。准备阶段对应玩家选招后的瞄准状态，应能等待目标与取消；视觉蓄势包含在原动作内，出招机会与费用沿用技能规格。

动作先选已有完整动画组并对齐实际 textkey：主手单剑可用原生 Flourish 动作，副手用原生 Offhand 动作；范围挥斩参考 Cleave，冲阵保留 Rush，人物移动保留 Jump／Fly。御剑用指剑、引剑或挥剑发令，飞剑在动作事件处出现。动作选型与原创骨骼动画是两项工作；自定义动画若后续制作，需同时处理不同种族、性别、体型与武器组合的映射。

下列节奏是 AllSpark 试样目标，最终跟随动画事件与实际结算校准。常态命中可用约 0.10 秒亮峰及 0.15—0.30 秒消散；气流、雾与巨剑余势可以稍后消散，人物已经能够接续下一次出剑。多段招式让每一段都可识别，命中或落空分别反馈；视觉间隔不自行新增伤害阶段或等待时间。

**太玄的优化重点是精确的出剑轴线。** 准备时少量气息归于剑尖，释放在匹配的 Cast 事件发生，随后用单一细锋贯入。照隙先验证单点轮廓，再扩展追星的四个独立读点；一线天需要单独的长直剑路表现，当前局部 Impact 原型没有绑定全距离 Beam，不能据其编译成功声称 30 米穿墙长锋已经实现。普通技能沿用实际可达轨迹与目标规则。

**天倾的优化重点是剑体与重量。** 先验证飞行巨剑的实际长轴、剑尖朝向和近景体量，再做逆锋宽扫、破阵锋楔、坠世下坠。落剑前保留暗剑身轮廓，撞击瞬间再亮刃并扩张冲击波；烟尘和余势随后降亮，不遮盖敌人、真实范围边界与下一次攻击。一次重斩只有一个主峰，三剑绝技才按原规格出现三个峰值。当前尺寸倍率是首批试样，人物身高 3—5 倍与八向巨剑阵仍是后续画面目标。

**血魇的优化重点是红雾可见与刃口清楚。** 当前飞行红雾保留原版初始粒子数 `4,4`、粒子寿命 `1.5—2 秒`与白灰粒子颜色渐变；红色来自原生材质的 `SmokeColor=(0.4590799,0,0)`。Uniform Scale 乘 `0.40` 后实际尺度渐变约为 `0.8—1.8`，持续发射为 `6 个／秒`；Lead In／Loop 各 `0.1 秒`，Lead Out `2.1 秒`，包围组件覆盖 `2.3 秒`。这一修订让原生 8×8 flipbook 有时间显出烟雾形态，已在 AllSpark 预览确认可见；仍需验证飞剑飞行时的拖尾、结束发射和末尾散尽。命中雾使用独立参数，不能把上述飞行数值套用到 Impact。掠血先验证单剑撕雾，连城与无生再按实际段数递进；癫狂以回卷力度和剑影层次增强，不自行增段。

三派优化动作目前仍需在已复用的完整动画组、主副手事件与不同 rig 上选择和校准。本轮没有制作分支专属的新骨骼动画；血雾、巨剑和局部贯刺原型也不能替代多段 helper、领域与团队技能的动作验证。行歌现有原型采用较轻的青绿剑体与成对护弧，后续仍按接应、交接和同伴真实跟进的方案扩展。

### 核心代表技

**太玄：流光追星与玄极·一线天。** 追星先以四道细长气剑形成有层次的瞄准轮廓，再逐剑汇入同一目标；四次独立命中各有一个小而锐的亮峰。一线天将多股剑意收束成单一长锋，从施展者贯向选定剑路，沿 30 米×2 米路线保持一眼可读的方向；击中不同敌人的局部剑痕按实际结算出现。穿过墙体时剑意继续贯行，墙体保持原样。

**天倾：天剑坠世、八方灭阵与天地剑劫。** 坠世呈现升起、巨剑下坠、落点放射冲击三个读点，9 米落区与随后 6 米余威分开表达。八方灭阵以八柄巨剑沿八个方向同时打开身周 18 米范围，中心到外围的剑势占据战场尺度；天地剑劫则在同一个 9 米区域依次落下三柄巨剑，三次重量峰值清楚，击倒与破甲反馈服从首次命中的规则。巨剑可以使用较长的残影和尘浪收尾，最亮峰值集中在撞击瞬间。

**血魇：血影连城、血海噬灵与血魇·无生。** 连城以四段红色血雾追斩构成猎杀路线，每段随实际近身／御剑选择调整剑路；移步后的旧雾迅速散去，新的剑尖持续引导视线。血海的随身边界由低伏红雾与内旋剑迹组成，周期出剑时雾被锋线划开，掠夺回流集中回到施展者。无生凝出三个红雾持剑影形，每影两剑，共六段；影形由剑与雾构成，起招后显现、段间收拢、终段散去，不新增召唤物或独立回合。

**行歌：同舟破浪、风雨同归与仗剑行歌。** 合击先有施展者的剑路与引导手势，再让同伴实际出手形成回应；施展者落空仍保留引导。分担发生时，一段短护弧从受护同伴承接到行歌，日常循环只保留较淡的护持标记。终极以队友节点与开放剑弧表达共同增益，符合条件的攻击生效时再发出单次御剑呼应；跟进使用清楚的剑形，原攻击与呼应的命中峰值分开。

## 5. 动作、分段与范围的制作约束

技能共有 44 个命名设计键，实际原生 Stats 还包括容器、主副手、附赠追加、癫狂投入与内部结算段。技能容器负责展示选项，效果应落在实际施展的子项上。换手、换费与投入层数沿用对应招式的核心形状，投入选项通过当次真实快照决定表现强度。

周期出剑、护体反击、天崩主目标重击、三剑落击、行歌合击与御剑呼应都需要独立命中反馈；人物完整起势只在需要的阶段播放。内部 helper 的动作是否打断、重复或抢占主施展，需要在真实 SE 环境观察，不能仅凭原生字段完整就判定节奏通过。

命中、落空、豁免减半与免疫遵循各招真实结果。减半可保留剑路并降低局部命中反馈；落空让剑路从目标旁掠过；免疫目标不显示成功破防。癫狂投入、疗伤、饮血与回元的读点以实际发生事件为依据。友方受伤规则按天倾两门终极现有规格执行，持续增益与伤害仍分别处理。

领域循环随人物移动，边界对应真实半径；周期爆发结束后回到较淡循环。状态到期、倒地待救或死亡时停止新增粒子，并按照结束阶段散去。用户连续出剑、多个领域重叠与多人合击时，仍需能看清目标、剑路和地面结算范围。

## 6. 按官方文档实施的顺序

1. **AllSpark 制作与编译。** 先放完整生命周期的 Bounding Sphere／Box，再制作剑模型、轨迹、粒子与材质。循环准备、投射物与状态安排 Lead In／Loop／Lead Out；保存 `.lsefx` 后用 Build → Compile Effect 产生 `.lsfx`。参考人物与地面仅用于预览的组件应在编译时排除。官方给出的示例秒数作为教程参数，具体节奏按本招校准。[VFX Part 1](https://docs.baldursgate3.game/VFX_%E2%80%93_Part_1:_Making_Effects)
2. **创建 Effect resource。** 在 Resource Manager 导入编译效果，名称与效果文件保持一致。每个效果源拥有对应登记；相同源文件重复创建多个 VFX resource 会触发官方说明的错误。[VFX Part 2](https://docs.baldursgate3.game/index.php?title=VFX_%E2%80%93_Part_2:_Creating_Resources)
3. **创建 MEI 并绑定技能／状态。** 为准备、释放、目标或持续阶段分别指定效果资源、骨骼与 textkey，绑定相应 Stats 字段。MEI 对象切换后等待面板完成更新再编辑。保持动画事件与 MEI 的触发事件匹配。[VFX Part 3](https://docs.baldursgate3.game/VFX_%E2%80%93_Part_3:_Assigning_and_Testing_Effects)
4. **创建飞剑 Projectile root template。** 飞行剑体与尾迹进入 Trail Effect ID，命中进入 Impact Effect ID，再指定 Cast Bone Name 与运动参数；Stats 的 Trajectories 引用该模板 GUID。逗号分隔的模板是路径失败后的候选，分号才区分多投射物／目标组，不能把候选数量当作出剑次数。[VFX Part 4](https://docs.baldursgate3.game/index.php?title=VFX_%E2%80%93_Part_4:_Advanced_Information)、[Projectiles](https://docs.baldursgate3.game/index.php?title=Projectiles)
5. **匹配动作与不同 rig。** 复用 SpellAnimation 时保留完整组与 CastTextEvent 配对；制作新动作时，为多 rig 动作建立 Shortname 与对应 AnimationSet 映射，并验证大小体型、性别与主副手。官方 Shortnames 指南说明了这一映射过程。[基本技能教程](https://docs.baldursgate3.game/Making_a_Basic_Spell)、[Animation: Creating Shortnames](https://docs.baldursgate3.game/index.php?title=Creating_Shortnames)
6. **Game Mode 实际施展。** 按官方教程载入测试关卡，进入 Game Mode，用 `addDebugSpell <完整技能技术名>` 授予具体施展子项；观察准备、取消、释放、飞行、命中与消散，并记录相应动画事件与日志。Common 首批通过后再扩展已制作阶段的启用清单。SE 管理的领域、反击、合击与生命周期另做相同版本的客户端测试。[官方技能测试流程](https://docs.baldursgate3.game/Making_a_Projectile_Spell)、[官方 MEI 测试流程](https://docs.baldursgate3.game/VFX_%E2%80%93_Part_3:_Assigning_and_Testing_Effects)

制作命名使用 `VFX_ESC_{Style}_{Phase}_01`，分支为 Common、Taixuan、Tianqing、Xueyan、Xingge，阶段为 Prepare、Cast、Impact、Status、Projectile。Projectile 阶段是飞行尾迹的 Effect resource；其 root template、Effect resource 与 MEI 分别登记。只有实际完成的分支／阶段进入启用清单，未完成资产不作为现有可用资源绑定。

## 7. 首批与分支验收重点

共同御剑主手与三派代表子技已取得成功施展和命中记录；下一步在同一版本补齐飞剑朝向、尺度、尾迹、Impact 与消散的逐帧观察，并记录连续施展和多人同屏性能。太玄照隙、天倾裂天和血魇掠血先完成这层视觉验收，再扩展副手、近身、落空、取消准备，以及追星／一线天、天剑坠世／八方灭阵、血影连城与行歌的问路／乘风破围。复杂多段、领域与团队招式按各自机制另行验收；正式包、实际客户端与 SE 生命周期的验证不能从 Toolkit 命中记录中推定完成。

验收记录区分 AllSpark 预览、效果编译、资源与绑定、Toolkit Game Mode、SE 客户端行为与正式安装。每次记录具体技能子项、版本、关卡／目标与观察阶段；单一模型预览、单次命中或资源解析通过，都只证明已观察到的部分。完成本文件的设计不改变第 1 节的当前实施状态。
