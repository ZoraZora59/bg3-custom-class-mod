01一页结论

  • 自创职业是官方明确支持的 mod 类型。Larian 的 Toolkit 文档有逐步教程《Adding Classes and Subclasses》，mod.io 官方准则把 "Classes and Subclasses：Create new class types" 列为支持项。
  • 职业 mod 的主体不需要 Script Extender。进阶表、被动、法术、资源、反应全部由纯数据（.lsx 表 + stats .txt）驱动；官方 41 个 Functor 与 Stats 表达式（含 ClassLevel(<class>)）足够表达绝大多数职业特性。SE 留给运行时逻辑与自定义 UI，做成可选模块。
  • 骨架只有两个文件。ClassDescriptions.lsx（职业是什么）与 Progressions.lsx（每级得到什么）通过 TableUUID 关联；再加本地化 xml 与 300×300 类图标即可出现在角色创建界面。
  • 第一个 mod 做"全新职业"。零进阶冲突、可上主机；给原版职业加子职业才涉及 Patch 7 合并节点与 Compatibility Framework（依赖 SE）。
  • 工具链在 2026 年仍然活跃但有门槛。Toolkit 仅 Windows，官方门槛 32 GB 内存 / 8 GB 显存 / 约 160 GB 磁盘；LSLib 1.20.4、Multitool 0.10.6、BG3MM 1.0.12.9、BG3SE v32（2026-06，支持 Patch 8）。ModFixer 已不需要，类图标已不依赖 ImprovedUI，Vortex 不推荐。
  • 最贵的坑都在元数据与顺序上。meta.lsx 的 Folder / Name / 目录名不一致、UUID 复用、Version64 不更新、先填 DisplayName 后建本地化、两个 mod 管理器混用、子职业整节点覆盖、缺 13–20 级节点导致黑屏。
  • 法务上完全自创最安全。借用 SRD 机制附 CC-BY-4.0 署名即可；Artificer、Tasha's 子职业、Blood Hunter 都不在 SRD。mod.io 官方页称启用任何 mod 后成就会被禁用。
  • 多语言从架构上就是免费的。所有玩家可见文本只经 handle 引用，同一 handle 在官方 15 种语言目录里复用；支持一种新语言 = 多一个 Localization/<Language>/ 目录和一份同 handle 的 xml。方案：英文为源，简/繁中文人工维护，其余 12 种随包发布（loca_sync.py 占位 → 机翻初稿 → 社区校对），"无裸 handle"作为发布门槛。
  • 1–2 人就能跑通。头部职业 mod 多为极小团队；每个 mod 的必需职能是所有者、设计/平衡、数据实现、兼容性、图标（可用 CC 素材）、测试、社区/文档，脚本、VFX、多语言可选。

04职业 mod 的数据结构

官方教程与社区手写教程指向同一套文件；Toolkit 的 UUID Object Editor 本质上是这些表的表格视图。

Mods/<Mod>/meta.lsxFolder = Name = 目录名；UUID 终身不变；Version64 每版重算
Public/<Mod>/ClassDescriptions/ClassDescriptions.lsx职业与子职业各一条：Name、UUID、ParentGuid（子职业）、ProgressionTableUUID、PrimaryAbility、BaseHp/HpPerLevel、ClassEquipment、热键栏列数之和 = 16
Public/<Mod>/Progressions/Progressions.lsx同 TableUUID 的 1..12 级节点：Boosts、PassivesAdded、Selectors（SelectSpells / AddSpells / SelectPassives / SelectSkills / SelectAbilityBonus）、AllowImprovement、SubClasses、IsMulticlass 行
Public/<Mod>/Lists/*.lsxSpellLists / PassiveLists / SkillLists / AbilityLists，Selectors 按 UUID 引用；可复用原版列表
Public/<Mod>/Stats/Generated/Data/*.txtPassive.txt / Spell_*.txt / Status_*.txt / Interrupt.txt：new entry / type / using / data；被动三件套 StatsFunctorContext + Conditions + StatsFunctors
Mods/<Mod>/Localization/<Lang>/*.xmlcontentuid = handle（任意无空格字母数字串），English / Chinese / ChineseTraditional；先建文件再填 DisplayName
Mods/<Mod>/GUI/Assets/ClassIcons/<Name>.DDS300×300 PNG 经 Convert UI Assets 转 DDS；文件名 = Name；hotbar/ 子目录放小图；Patch 7 起不需要 ImpUI
Public/<Mod>/Stats/Generated/Equipment.txtEQP_CC_<Mod> 起始装备，填进 ClassEquipment

官方 Toolkit 流程要点

  • Progressions：每级一行，UUID 唯一、TableUUID 共享，ProgressionType 0 = class / 1 = subclass / 2 = race；子职业在父职业解锁级行的 SubClasses 列登记。
  • ClassDescriptions：LearningStrategy = AllChildren，CharacterCreationPose = 0f07ec6e-4ef0-434e-9a51-1353260ccff8，多职业行 IsMulticlass = Yes。改完保存并重启 Editor。
  • 快速测试：加载 Basic_Level_A → Game Mode → 悬停头像 Ctrl+Shift+L 升级 → Add Class；Ctrl+Shift+F11 调试台 addDebugSpell、reloadLoca。
  • 数值表达式：ClassLevel(<class>)、ProficiencyBonus、SpellCastingAbility、ResourceRoll()、foreach()、max()；Functor 列表 41 个（ApplyStatus、DealDamage、RestoreResource、UseActionResource、Summon、CreateSurface、UseSpell、ResetCooldowns…）。
  • Boosts / Conditions 没有官方参考页；权威来源是社区 wiki 与解包的原版 Stats 文本。

05发布渠道与规则

mod.io（官方管线）

Toolkit → Project Settings → Authenticate → Publish → 自动扫描 → Go live。覆盖 PC / PS5 / Xbox / Mac / GeForce NOW；主机需人工审核并排除 .exe/.dll/.zip、新可玩种族、shader 改动、增加裸露暴力。依赖要在 Toolkit 与 mod.io 各设一次；可声明 Conflicts 让游戏自动禁用冲突 mod。

Nexus Mods

网页上传 pak/zip；后续版本可用官方 upload-action 自动化（Upload API 仍是 beta，只支持更新既有 mod）。SE 依赖的 mod 走这里。两平台 UUID 相同、Version64 同步，否则玩家联机会因版本不一致失败。

官方硬规则

原创或已授权；不得与可识别的第三方品牌、角色相似；不得解锁付费或成就物品；缩略图不得裸露；AI 生图需遵守服务条款；未获许可不得把他人 mod 扩展/翻译后署原作者。

玩家侧事实

启用任何 mod 后成就自动禁用（mod.io 官方准则页）；联机所有人需相同 mod；两 mod 改同一 ID 条目时加载顺序靠后者胜出；Larian 声明除关键修复外无长期支持能力。

07双机环境与基建

Mac：编辑 / 设计 / 脚本

VS Code + bg3-mod-helper / bg3txt-formatter / SE 片段 + LuaLS（ExtIdeHelpers.lua）；Python 脚本生成 UUID / handle / Version64、静态校验；图标源图；git 仓库是唯一事实源。可选实验：.NET 8 跑 Divine（工程引用 C++/CLI 原生库，未验证）。

Windows：工具 / 验证 / 发布

BG3 + Toolkit Data DLC + Toolkit；LSLib 1.20.4；Multitool；BG3MM；Script Extender（控制台 + VS Code 调试器）。pull → 打包（Divine / Toolkit Publish Local）→ 部署到 %LOCALAPPDATA%\Larian Studios\Baldur's Gate 3\Mods → 游戏内按测试矩阵验证 → 结果回流 issue。先核对硬件是否达 Toolkit 门槛。

仓库布局与规范

Baldur's-Gate-Mod/
├── docs/ research/ templates/ scripts/
├── mods/<ModName>/Source/{Mods,Public}/<ModName>/   # Divine create-package 的源根
├── assets-src/      # 图标源图（可 LFS）
├── build/           # .pak 产物（.gitignore）
└── reference/       # 解包的原版数据（.gitignore，不入库）
  • .gitattributes 固定行尾（lsx/txt/xml/lua = LF），pak/lsf/dds/gr2/loca 标 binary；pak 不入库，走 Releases。
  • 版本：git tag vX.Y.Z ↔ Version64；官方建议 Major = 新内容，Minor = 修复，Revision = 微调，Build 自动递增并用于联机版本匹配。
  • CI 先不做；稳定后用 windows-latest + LSLib + Nexus upload-action；mod.io 只能经 Toolkit 发布。
  • 测试存档集（1/3/5/12 级 + Withers 可用）随 Releases 分发给测试者。

11汉化别人的 mod：改原 mod，还是做独立汉化 mod？

2026-09-02 追加的专题。问题只有一个：想给自己喜欢的 mod 做中文，是直接改那个 mod，还是另做一个 mod。

结论：做独立汉化 mod。一个只含 Localization/Chinese/<名字>.loca 和 Mods/<Folder>/meta.lsx 的小 pak，放在原 mod 之下（更晚）加载。bg3.wiki、Nexus 提交规则、Larian/mod.io 准则、3DM 中文教程第二版和 N 网上的 CHS 条目都指向这一种做法。直接改原 mod 只适合"自己玩不分发"，或者把译文交给作者合并进原 mod。
维度直接改原 mod（解包 → 加中文 → 重打包）独立汉化 mod
原 mod 更新后每次重新解包整个新版、重放译文、重打包只翻新增/变更的 handle；原 mod 没加文本就不用动
许可与平台规则等于再分发他人全部资产；Nexus 规定翻译只能作为与原文件配合的附加文件，未获许可可被删除；mod.io 要求翻译前取得许可只含你的译文与原 mod 的 handle；Nexus 上传时直接标记为已有 mod 的翻译，出现在原页的 Translations 区
身份与联机同名 pak / 同 UUID 会互相顶替、被当成另一版本；联机时全员都得用你改的版本新 UUID、新 Folder；全员多装一个小 mod 即可，对英文客户端无副作用
主机不可能经官方 Toolkit 发到 mod.io 并过审才可能
不走 loca 的文本（Lua / JSON 硬编码、贴图）可以直接改文件覆盖不到；只能请作者改用 handle 或 MCM Handles
社区观感2023 年早期教程的做法，现被视为过渡形态主流

引擎层面必须知道的六件事

  • 缺 handle 不会显示裸 handle。引擎带回退池，查不到时回退到另一池（基础游戏实证为英文），全部池都没有才显示 "Not Found"。"只带 English 的 mod 在简中客户端显示英文"是高置信推断、无一手明文——所以汉化是体验问题，不是能不能玩的问题。
  • 多个 pak 的同语言文本按 handle 逐条合并，后加载者覆盖；同路径同名文件则整体替换。"翻译补丁放在原 mod 之下" = 更晚加载 = 优先级更高。汉化 pak 排在原 mod 之后，且 loca 文件名与原 mod 不同。
  • contentuid 与 version 原样保留。引擎查表只比较 handle、忽略 version；覆盖靠加载顺序，不靠抬 version。
  • 手工打包的 pak 里必须是 .loca。xml 只是 Toolkit 项目的源格式；Multitool 会自动把 x.loca.xml 转回，但会合并多个 xml。
  • 目录名固定：简体 Localization/Chinese/，繁体 Localization/ChineseTraditional/。
  • Script Extender 的 Lua 硬编码字符串、无 Handles 的 MCM 界面、贴图上的字都不走 loca；SE 的 Ext.Loca.UpdateTranslatedString 能运行时替换但只写内存。

Mac 上能做什么

文本层全部：scripts/loca_convert.py（纯 Python 的 loca↔xml，按 LSLib 源码实现，已做字节级往返自测，尚未用游戏真实文件验证）、loca_sync.py 做新旧版本 diff。解包/打包目前仍交 Windows；Rust 的 maclarian 与 Python 的 bg3-forge 声称能在 Mac 原生解/打包，均为 2026 年新项目，未实测。

Windows 上的工具

LSLib ConverterApp / Divine（事实标准）、Multitool（已迁至 GitLab）、官方 Toolkit（mod.io 发布必经）。3DM 教程用的 BG3 LocaHelper 源码已于 2024-01 被 DMCA 下架，仍能用但无维护。AI 初稿工具：bg3-mod-ai-translator-zh（跨平台）、BG3ModTranslation、Icosa、Gemini 版 BG3 Mod Translator（均需人工校对）。

汉化专用坑：目录名不是 Chinese、xml 没转 loca、游戏语言没切、汉化排在原 mod 之上被其自带的 Chinese 覆盖、与原 mod 同名/同 UUID、没有 meta.lsx 的 override 型 pak（Patch 7 后失效）、xml 里把 &lt;LSTag&gt; 还原成真实标签、只有一个人装汉化导致联机不匹配。完整对比、步骤命令与来源见仓库 docs/09-translating-existing-mods.md 与 research/H–K。

方法与局限。研究分两轮：第一轮 6 个并行子课题（工具链、结构、案例、踩坑、脚本与基建、团队工作流）加主控补读官方文档，共 7 份报告、322 条引用条目；第二轮"汉化别人的 mod"3 个子课题（loca 格式与工具、引擎行为、社区惯例与政策）加主控浏览器直读，共 4 份报告、约 180 条引用条目（跨报告有重叠）。Nexus 在内置浏览器里也被人机验证拦下，未绕过。Nexus 页面对抓取工具返回 403、mod.io 与社区 wiki 为 JS 渲染，因此推荐数、依赖列表、Credits 多来自搜索摘要；官方 Toolkit 文档与 mod.io 准则已用浏览器直读核对。所有"游戏内行为"类结论尚未在游戏内验证，对应的验证清单见第 09 节。完整报告与来源表在项目仓库的 docs/ 与 research/。
